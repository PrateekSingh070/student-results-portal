# Implementation notes

**Stack and scope.** Flask, Jinja, SQLite and Waitress keep the app in one process and remove the need for a frontend build or separate database service. I built the importer first because accepted records feed both other screens. The browser uses normal forms and server-rendered pages. JavaScript adds drag-and-drop, a filename preview and an import status message. The JSON endpoints use the same validation and queries as the forms.

**Data and validation.** A normalized student ID identifies one current result. IDs and sections are uppercased, names are trimmed and internal whitespace is collapsed, and emails are lowercased. The email check accepts ordinary mailbox syntax with a dotted domain. Date validation uses the server’s calendar date, with 5 and 25 inclusive. Each mark is written in plain decimal notation and must be between 0 and 100. Marks are stored as text so the report can calculate and grade with exact decimal values. Case-folded name and ID substring search with a stable sort and page size of 25 works at the expected scale.

**CSV errors and duplicates.** Required headers identify comma, semicolon or tab exports. A structurally readable record with a valid ID claims its first occurrence even if other cells fail. Later occurrences are rejected. Records with the wrong field count get a row-level error. For malformed quoting or excessively long fields, the parser reports the starting physical line and resumes at the next physical line. Quoted multiline fields are supported up to 32 lines per record to bound recovery. A file with a bad header or encoding, no student rows, or more than the allowed size or row count fails as a whole. The on-screen and downloadable error reports identify the line, the field when available and what to fix.

**Retries and performance.** Existing IDs are preserved because the file has no term or update indicator. Exact retries are keyed by the SHA-256 of the original bytes. A single SQLite transaction commits the student inserts, counts and row issues together. SQLite serializes concurrent writes and the digest is checked again inside the transaction. A 5 MiB and 20,000-row limit keeps the synchronous request bounded and the page signals when work is in progress. Uploaded CSV bytes are discarded after processing.

**Next steps.** Add authentication, access logs and a retention policy before using real student records. Add a term identifier and explicit correction workflow before allowing an existing student’s results to be replaced. A background job would be appropriate if imports grow past the current limits or request time becomes a problem.
